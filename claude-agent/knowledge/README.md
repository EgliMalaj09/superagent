# Knowledge base

What the user has learned and liked. Each kind of knowledge lives with the studio that uses it; this file is the map.

| File | What's in it | Who reads it |
|---|---|---|
| `../ABOUT-ME.md` | Who the user is, the two channels, clients, goals | The master, every task |
| `<studio>/animation-library/CREATOR-PROFILE.md` | **pattern.io**: genres, process, visual taste, likes and dislikes | `animation-agent`, master |
| `<studio>/animation-library/TASTE.md` | Running animation taste notes | `animation-agent` |
| `<studio>/animation-library/docs/style-guide.md` | **Every animation look** in one catalogue: our kits and style cards, plus huashu-art-motion's 9 explainer grammars and 35 art styles, with what each is good for | `animation-agent`; the master when proposing a style |
| `<studio>/animation-library/references/<style>/STYLE.md` | **Animation style cards** from references the user liked | `animation-agent` |
| `<studio>/claude-editor/styles/<style>/STYLE.md` | **Editing styles** (real footage, captions, overlays), e.g. `arzi-dental-promo` for Arzi | `editor-agent` |

## How it grows
- **Same turn**: when the user likes or rejects something, write it down where it belongs and say in one line what
  was saved. A style → that style card's taste log (dated, newest first). Channel or general taste → `TASTE.md` /
  `CREATOR-PROFILE.md`. Who the user is or what they're aiming for → `ABOUT-ME.md`.
- **At the end of a job**: a short `MAKING-OF.md` in the project, plus any new rule in the right file above.
- **When two rules disagree, the newest wins**; edit the old line instead of keeping both.
- **New style**: a new `STYLE.md` card in the right studio (animation or editing).
